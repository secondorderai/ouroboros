Inside the runner

The controller is in charge

The tested TypeScript program carries the workflow from one stage to the next. It creates worktrees, validates Codex reports, commits and merges changes, manages checkpoints, and updates GitHub.

OwnsState transitions, Git writes, GitHub writes, credential write-back.
Connects toCodex CLI, Git, GitHub REST/GraphQL, Actions artifacts.
Human control remains explicit. You approve implementation and decide whether to merge. The generated workflow does not automatically merge or deploy the application.

Two durable stores, different contents

Login credentials stay in environment secrets. Encrypted artifacts preserve the work so the next runner can continue.

SUBSCRIPTION LOGIN

CODEX_AUTH_JSON

The managed ChatGPT login file. Seeded into an isolated runner directory and refreshed by Codex.

CREDENTIAL PERSISTENCE

CODEX_AUTH_WRITE_TOKEN

A GitHub token scoped to updating the environment secret. The controller uses it to save the refreshed login.

CHECKPOINT ENCRYPTION

CODEX_SDLC_STATE_KEY

A base64-encoded 32-byte key. The controller uses AES-256-GCM to encrypt and authenticate saved work.

GITHUB OPERATIONS

GITHUB_TOKEN

Provided by Actions for routine repository, issue, and artifact operations. An optional CODEX_GITHUB_TOKEN publishes PRs and can start PR CI without the bot approval requirement.

The login refresh loop

1
Wait for the subscription job lock

Execution jobs share one concurrency group. Teammates run within one Codex process on one runner.

2
Read environment secrets at job start

The codex-sdlc environment must be restricted to the default branch. The next job reads the login saved by the previous job.

3
Restore a private auth directory

The controller writes auth.json under an isolated CODEX_HOME. GitHub write tokens are removed from Codex and build subprocess environments.

4
Codex authenticates and refreshes

The CLI uses the ChatGPT login for model requests and may update its local credential file.

5
Write the current file back to GitHub

After each phase and during cleanup, the controller uses the writer token to replace CODEX_AUTH_JSON.

6
Remove local credentials and release the VM

Session records can be checkpointed; the authentication file is excluded. A failed credential write-back blocks automatic continuation.

Inside the encrypted artifact

  • Issue requirements, approved plan, tickets and issue mappings
  • Attachments, audit/review reports and execution records
  • Stage, ticket status, base/head commits and original deadline
  • Native sessions and Git bundles containing unfinished worktrees

Outside the implementation branch

  • Generated plans, ticket manifests, and audit reports live in artifacts
  • The issue’s bot comment holds status and the artifact pointer
  • Artifacts are bound to the repository, issue and pipeline identity
  • Auth files, restored config, hooks and plugins are excluded from session recovery
Retention matters: checkpoints use 14-day retention, subject to repository policy. Keep the same state key while you need to recover existing pipelines.

The requested public-repository subscription setup differs from OpenAI’s recommended trusted private automation pattern. See OpenAI’s authentication guidance and GitHub’s secret timing.

Automatic continuation deadline

The five-day deadline starts at implementation approval and is preserved across automatic continuations. Waiting for plan approval does not consume it. An explicit maintainer resume authorizes a fresh window. Scheduled runs can be delayed by GitHub.

Saved does not mean complete. Integrated changes can be published in a draft PR. Unmerged worker changes remain in the checkpoint. Missing reports, unfinished workers, or failed checks never satisfy the ready-for-review gate.
